## Опис
Четвертий етап розробки пошукового рушія `findex`. Проєкт переведено на строгу типізацію (Pyright strict), покрито модульними та Property-based тестами (`pytest`, `hypothesis`), запаковано як глобальний CLI-інструмент за допомогою `uv`, `Typer` та `Rich`. 

## Тестування та покриття коду
Загальне покриття коду тестами становить **57%** (>30 тестів). 
**Що навмисно залишилося поза тестуванням:**
Модуль інтерфейсу командного рядка (`cli.py`) та операції читання/запису великих обсягів даних на диск навмисно не покриті тестами на 100%. Це зроблено для того, щоб уникнути сповільнення CI/CD пайплайну важкими I/O операціями та не дублювати тестування візуального виводу (бібліотеки `Rich` та `Typer`), зосередившись на логіці та математиці.

## Архітектура та Об'єктна модель
- **Dunder-методи:** Клас `Index` реалізує магічні методи `__len__`, `__contains__`, `__getitem__`, `__iter__`, `__repr__`. Індекс поводиться як стандартна колекція Python.
- **Властивості:** Використано `@property` для `num_docs` та `@functools.cached_property` для `avg_doc_length`, що значно прискорює обчислення BM25.
- **Duck Typing (Протоколи):** Ранжування реалізовано через протокол `Scorer`. Алгоритми `TfIdf` та `BM25` взаємозамінні (без прямого наслідування).
- **Управління контекстом:** Завантаження індексу відбувається через `with open_index(path)`.

## Парсер запитів та Декоратори
- **AST Парсер:** Реалізовано алгоритм рекурсивного спуску для побудови синтаксичного дерева (`AND`, `OR`, `NOT`).
- **Декоратори:** 
  - `@timed` для логування часу виконання.
  - Кешування дерева запитів для миттєвого пошуку при повторних викликах (Cache Hit).
- **Сніпети:** Витягується вікно тексту (±80 символів) із підсвічуванням ANSI-кодами (або через таблиці `Rich`).

## Оцінка якості пошуку (Precision@5)
Для порівняння якості алгоритмів було відібрано 10 запитів із ручною розміткою "має бути в топ-5". Середнє значення P@5 для TF-IDF склало **0.68**, а для BM25 — **0.82**. BM25 стабільно показує кращі результати завдяки згладжуванню частоти термінів та нормалізації за довжиною документа.

## Інструкція зі встановлення та запуску

Для керування залежностями та пакування використовується `uv`.

**1. Встановлення як глобального інструменту:**
З вихідного коду (у папці проєкту):
`bash`
uv sync
uv tool install 

**2. Побудова індексу:**
Збирає документи із вказаної папки та зберігає готовий індекс у файл (використовується прогрес-бар Rich)
`bash`
findex index data/ index_with_pos.bin

**3. Запуск пошуку:**
Пошук з форматованим виводом у вигляді таблиці (за замовчуванням алгоритм BM25):
`bash`
findex search index_with_pos.bin data/ "програмування AND python"

Опціональні прапорці:

    --scorer tfidf — використати алгоритм TF-IDF замість BM25.

    --json — вивести результати у форматі JSON у stdout (зручно для перенаправлення > results.json).
    
**4. Діагностика (Логування):**
Замість print тепер використовується logging. Для відображення часу виконання та відладочної інформації додайте прапорці -v (INFO) або -vv (DEBUG) перед командою:
`bash`
findex -vv search index_with_pos.bin data/ "київська русь"
