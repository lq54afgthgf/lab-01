# Лаб 3. Рейтинг і об'єктна модель: dunder-методи, протоколи, декоратори

## Опис
Третій етап розробки пошукового рушія `findex`. Інвертований індекс перетворено зі звичайного набору словників на повноцінний Python-об'єкт завдяки реалізації Data Model (dunder-методів). Boolean-пошук замінено на систему ранжування, додано парсер мови запитів (AST) та генерацію сніпетів.

## Архітектура та Об'єктна модель
- **Dunder-методи:** Клас `Index` наслідує `collections.abc.Mapping` та реалізує магічні методи `__len__`, `__contains__`, `__getitem__`, `__iter__`, `__repr__`. Тепер індекс поводиться як стандартна колекція Python.
- **Властивості:** Використано `@property` для `num_docs` та `@functools.cached_property` для `avg_doc_length`, що значно прискорює обчислення BM25 (уникає перерахунку середньої довжини для кожного документа).
- **Duck Typing (Протоколи):** Ранжування реалізовано через протокол `Scorer`. Алгоритми `TfIdf` та `BM25` взаємозамінні, оскільки обидва мають метод `__call__` із відповідною сигнатурою.
- **Управління контекстом:** Завантаження індексу відбувається через контекстний менеджер `with open_index(path)`, що гарантує безпечне управління ресурсами.

## Парсер запитів та Декоратори
- **AST Парсер:** Реалізовано алгоритм рекурсивного спуску для побудови синтаксичного дерева. Підтримуються оператори `AND`, `OR`, `NOT`, точні фрази (через позиції токенів) та угруповання дужками `()`. Вузли перевантажують оператори `&`, `|`, `~`.
- **Декоратори:** 
  - `@timed` (з використанням `functools.wraps`) для логування часу виконання пошуку та завантаження.
  - `@lru_cache` для кешування дерева запитів, що забезпечує миттєвий пошук при повторних запитах (Cache Hit).
- **Сніпети:** Для кожного знайденого документа витягується вікно тексту (±80 символів) із підсвічуванням знайдених термінів за допомогою ANSI-кодів.

## Sanity Checks (Перевірки ранжування)
Ранжування працює коректно, що підтверджується трьома базовими перевірками на нашому корпусі:
1. **Рідкісний термін vs Частий:** Документ, що містить рідкісне специфічне слово, отримує значно вищий бал (завдяки компоненту IDF), ніж документ, переповнений загальновживаними словами (наприклад, сполучниками).
2. **Насичення частоти (BM25):** 20-те повторення терміна в одному документі майже не збільшує його загальний бал (ефект параметра `k1=1.5`), що усуває проблему спаму ключовими словами порівняно з чистим TF-IDF.
3. **Нормалізація довжини:** Короткий документ з одним входженням терміна опиняється у видачі вище, ніж величезний лонгрід із таким самим одним входженням (завдяки параметру `b=0.75`, що штрафує за довжину).
