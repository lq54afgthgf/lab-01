# Лаб 1. Ітератори, генератори та ваш корпус

## Опис
Перший етап розробки пошукового рушія `findex`. Головною метою цієї лабораторної роботи є створення ефективного пайплайну для обробки великих обсягів текстових даних (дамп української Вікіпедії) без перевантаження оперативної пам'яті.

Реалізовано систему потокового читання документів та їх токенізації за допомогою генераторів.

## Інструкція з запуску
Для запуску тестів токенізатора:
`PYTHONPATH=src uv run pytest tests/`

Для запуску збору статистики та порівняння пам'яті:
`PYTHONPATH=src uv run python src/findex/stats.py`

## Правила токенізації
- **Unicode-нормалізація:** NFC (зведення складених символів до єдиного, наприклад `e` + `´` -> `é`).
- **Регістр:** Усі слова зведені до нижнього регістру через `casefold()`.
- **Фільтрація:** Зберігаються літери, цифри, а також дефіси та апострофи всередині слів (наприклад, `комп'ютер`, `будь-ласка`). Пунктуація видаляється.

### Порівняння: Жадібний (Greedy) vs Лінивий (Lazy) підхід
Під час розробки було проаналізовано дві стратегії обробки текстів. Вибір зроблено на користь лінивого підходу, оскільки він єдиний дозволяє працювати з дампами, розмір яких перевищує обсяг оперативної пам'яті.

| Характеристика | Жадібний підхід (Greedy) | Лінивий підхід (Lazy - наша реалізація) |
| :--- | :--- | :--- |
| **Споживання пам'яті** | $O(N)$ — завантажує весь гігабайтний файл у RAM. | $O(1)$ — пам'ять витрачається лише на поточну статтю/блок. |
| **Ризик OOM (Out of Memory)**| Високий. Скрипт впаде з помилкою пам'яті при обробці великого дампу. | Відсутній. Програма стабільно обробляє файли будь-якого розміру. |
| **Початок обробки** | Довга пауза (чекає повного завантаження файлу в пам'ять). | Миттєво (починає віддавати токени з першої прочитаної лінії). |
| **Реалізація в Python** | `.read()`, `.split()`, зберігання результатів у списках `[]`. | Ітерація по файлу `for line in f:`, використання `yield`. |

### Аналіз використання пам'яті
У "жадібному" підході пам'ять витрачається на завантаження всього масиву тексту через `f.read()` та створення гігантського списку всіх знайдених токенів одночасно через метод `re.findall()`. 

У "лінивому" конвеєрі ми читаємо файл по одному рядку (`for line in f`), а токенізатор віддає слова по одному через `re.finditer()`. У пам'яті одночасно перебуває лише один рядок тексту, а єдина структура, яка накопичує дані і споживає пам'ять — це агрегатор `Counter` (словник частот термів).
