# Лаб 2. Інвертований індекс: словники, хешування та пам'ять

## Опис
Другий етап розробки пошукового рушія `findex`. В рамках цієї лабораторної роботи реалізовано побудову інвертованого індексу над великим текстовим корпусом (дамп української Вікіпедії), серіалізацію структур даних на диск та систему Boolean-пошуку (оператори AND, OR, NOT) для знаходження документів за запитом.

## Архітектура та оптимізація
Для забезпечення ефективної роботи з великими текстами було застосовано такі рішення:
- **Оптимізація пам'яті:** Класи `Posting` (ідентифікатор документа та частота терміна) та `DocMeta` реалізовані через декоратор `@dataclass(frozen=True, slots=True)`. Використання `slots` дозволило відмовитись від створення словників `__dict__` для кожного об'єкта, що заощадило сотні мегабайтів оперативної пам'яті.
- **Однопрохідна обробка:** Підрахунок частоти слів виконується через `collections.Counter`, який ліниво споживає генератор токенів, уникаючи завантаження всього тексту документа в пам'ять.
- **Структура індексу:** Використовується `collections.defaultdict(list)`, де ключами є терми, а значеннями — списки постінгів, автоматично відсортовані за `doc_id`.
- **Опційні позиції токенів:** Реалізовано можливість зберігати позиції токенів у тексті (прапорець `--positions`). Розмір індексу на диску **без позицій** складає **403.38 MB**, а **з позиціями** — **468.51 MB**. Зберігання масивів позицій додає **65.13 MB** (+16.1%) до файлу індексу.
- **Серіалізація та безпека:** Збереження та завантаження побудованого індексу на диск реалізовано за допомогою вбудованого модуля `pickle`. Також додано підтримку `JSON`.  
**Увага:** Використання `pickle.load` для неперевірених (чужих) файлів є вкрай небезпечним. Модуль `pickle` може серіалізувати довільні об'єкти, і під час десеріалізації зловмисник може виконати довільний код на вашій машині. Ніколи не завантажуйте файли `.bin` з невідомих джерел.

## Рушії пошуку
Реалізовано два підходи до перетину, об'єднання та різниці списків документів:
1. **Алгоритм `merge` (Два вказівники):** Класичний підхід, який послідовно порівнює два відсортовані масиви `doc_id` за час $O(N+M)$.
2. **Алгоритм `set` (Множини):** Використовує вбудовану оптимізовану (на рівні мови C) структуру даних `set` у Python.

## Статистика індексу

- **Унікальних термів у словнику:** 442 172

### Бенчмарк пам'яті структур даних (Postings)
Вимірювання на підвибірці з 10 000 статей під `tracemalloc` для порівняння витрат оперативної пам'яті:

| Метод збереження | Пікова пам'ять | Аналіз (куди пішли байти) |
| :--- | :--- | :--- |
| **Звичайний `dataclass`** | 24.13 MB | Створюється словник `__dict__` для кожного об'єкта, що тягне величезні накладні витрати на хеш-таблиці. |
| **Dataclass (`slots=True`)** | 15.92 MB | Економія ~34% завдяки відмові від `__dict__`. Пам'ять виділяється лише під фіксовані дескриптори полів. |
| **Масив `array('I')`** | 6.22 MB | Найефективніший варіант (економія у ~3.9 раза). Безперервний блок сирих 32-бітних чисел (C-типу) без створення Python-об'єктів. |

### Аналіз використання ресурсів
1. **Пам'ять та завантаження:** Оскільки ми завантажуємо весь словник (442 172 терми) та всі списки постінгів для 866 898 документів у пам'ять із файлу `index.bin` (403.38 MB), процес десеріалізації під увімкненим `tracemalloc` займає ~180 секунд, а пікове споживання пам'яті під час пошуку складає ~5.45 ГБ.
2. **Швидкість пошуку:** Обидва рушії (`merge` та `set`) повертають абсолютно ідентичні множини документів (1 575 для `AND`, 114 189 для `OR`, 86 961 для `NOT`). На масивних операціях об'єднання (`OR`) та різниці (`NOT`) на сотні тисяч документів C-реалізація `set` дає виграш близько 3.5–7 секунд порівняно з циклом `while` у Python.

## Інструкція із запуску

**Побудова та збереження індексу:**
```bash
# Базова побудова індексу у форматі pickle (без позицій)
uv run python -m findex.index data/ --out index.bin

# Побудова індексу зі збереженням позицій токенів
uv run python -m findex.index data/ --out index_pos.bin --positions

# Побудова та збереження індексу у форматі JSON
uv run python -m findex.index data/ --out index.json
```

**Булевий пошук (`--engine merge` та `--engine set`):**
```bash
# Перетин (AND) — двовказівниковий merge та множини set
uv run python -m findex.search index.bin "були AND населення" --engine merge
uv run python -m findex.search index.bin "були AND населення" --engine set

# Об'єднання (OR) — двовказівниковий merge та множини set
uv run python -m findex.search index.bin "для OR як" --engine merge
uv run python -m findex.search index.bin "для OR як" --engine set

# Різниця (NOT) — двовказівниковий merge та множини set
uv run python -m findex.search index.bin "року NOT не" --engine merge
uv run python -m findex.search index.bin "року NOT не" --engine set
```
