# Лабораторна робота №6. Асинхронний краулер: `asyncio`

[![CI](https://github.com/lq54afgthgf/lab-01/actions/workflows/ci.yml/badge.svg)]

## Опис завдання

**Що вивчаємо:** Асинхронне програмування (`asyncio`); кооперативна багатозадачність та цикл подій (`Event Loop`); робота, обмежена вводом-виводом (`I/O-bound`); `asyncio.TaskGroup`, скасування задач і `asyncio.timeout`; глобальний і per-host семафори та черга; мережеві запити через `httpx` і тестування з `httpx.MockTransport`; механізми повторних спроб (`exponential backoff`, `jitter` та `Retry-After`); парсинг вебсторінок через `selectolax`; правила «ввічливого» скрапінгу та обробка `robots.txt`.

**Що зроблено в межах проєкту (Асинхронний краулер):**

1. Реалізовано асинхронний вебкраулер (`crawl` як асинхронний генератор) із використанням `asyncio.TaskGroup` та `httpx.AsyncClient` для неблокувального збору сторінок в один потік.
2. Додано канонізацію URL (`canonicalize`: нижній регістр схеми й хоста, сортування query-параметрів, відкидання якоря `#`) та множину `seen` для захисту від повторного обходу тих самих адрес.
3. Реалізовано дворівневе обмеження паралелізму: глобальний семафор (`--concurrency`) і семафор на окремий хост (`--per-host`) разом із мінімальною паузою `0.5 с` між запитами до одного домену.
4. Налаштовано функцію `fetch` із `asyncio.timeout(10.0)` та автоматичною обробкою збоїв (до 3-х повторів лише для HTTP `429`, `5xx` і таймаутів) через `exponential backoff` із `jitter` та врахуванням заголовка `Retry-After`. Інші `4xx` помилки не повторюються.
5. Створено `RobotsCache` для автоматичного завантаження, розбору та кешування правил `robots.txt` окремо для кожного хоста.
6. Реалізовано потокове збереження зібраних документів у `.jsonl` у міру надходження сторінок (без утримання всього корпусу в пам'яті), живу панель статусу через `rich.live.Live` та логування кожного запиту у `crawl.log`. Забезпечено повну сумісність із `iter_documents` (Лаб 1) та позацикловою індексацією `findex index` (Лаб 5).

## Етика обходу: дозвіл на краулінг та `User-Agent`

* **Дозвіл на краулінг:** Цільовий сайт `http://quotes.toscrape.com/` є публічною пісочницею (sandbox), спеціально створеною для тестування скрапінгу та краулінгу. Дозвіл на автоматизований збір даних є явним, а `robots.txt` не забороняє обхід.
* **Чесний `User-Agent`:** Усі запити виконуються з відкритим заголовком ідентифікації та посиланням на репозиторій проєкту:
  `User-Agent: FindexCrawler/1.0 (+https://github.com/Tserelenko/findex)`
* **Обмеження обсягу:** Параметр `--max-pages` жорстко обмежує кількість зібраних сторінок, після досягнення якої воркери у `TaskGroup` скасовуються, а клієнт `httpx.AsyncClient` закривається.

## Аналіз результатів та відповіді на контрольні питання

### 1. Чому 20 одночасних запитів в одному потоці для цієї роботи швидші за підхід Лаби 5?

Краулінг — це типова **I/O-bound** задача, де понад 95% часу програма нічого не обчислює, а чекає на відповідь від мережевого сокета.

* У підході Лаби 5 (`ProcessPoolExecutor`) для 20 одночасних запитів довелося б піднімати 20 окремих процесів ОС із великими накладними витратами на `spawn`, перемикання контексту ядра та серіалізацію HTML-текстів через `pickle`.
* Натомість у `asyncio` **один потік** кооперативно обслуговує всі 20 корутин через системний мультиплексор сокетів (`epoll`): щойно воркер викликає `await client.get(url)`, керування за наносекунди переходить іншому воркеру без блокування потоку й при мінімальному споживанні пам'яті (`Peak RSS` лише `8.68 – 32.42 MB`).

### 2. Чого коштує ліміт на хост (`per-host` + пауза `0.5 с`) і навіщо він лишився?

* **Чому швидкість на `concurrency=5` і `concurrency=20` однакова (`3.94 pages/sec`, `~50.7 с`):** Оскільки весь обхід відбувається в межах **одного хоста** (`quotes.toscrape.com`), швидкодія впирається у семафор хоста (`--per-host 2`) та примусову паузу ввічливості `0.5 с` між запитами до одного домену. Навіть коли створено 20 воркерів, одночасно звертатися до цього домену можуть лише 2, а решта 18 чекають на семафорі `host_sems[host]` (при цьому 20 воркерів споживають трохи більше пам'яті на власні стеки та чергу — `32.42 MB` проти `13.53 MB`). Повний потенціал `concurrency=20` розкривається при одночасному обході десятка різних доменів.
* **Навіщо він лишився:** Без ліміту на хост і паузи 20 воркерів миттєво б атакували один сервер десятками паралельних запитів, що призвело б до блокування IP-адреси або лавини відповідей `429 Too Many Requests`.

### 3. Де цикл подій зупинився б, якби індексація йшла всередині корутини?

Цикл подій (`Event Loop`) працює в одному потоці й може перемикати задачі лише в точках `await`. Якби синхронна CPU-bound індексація з Лаби 5 (`tokenize`, побудова інвертованого індексу `Posting` або серіалізація `save_index`) викликалася безпосередньо всередині корутини воркера:

* потік інтерпретатора був би заблокований обчисленнями на сотні мілісекунд без жодного `await`;
* на цей час зупинився б увесь цикл подій: таймери `asyncio.timeout` не спрацьовували б вчасно, готові мережеві відповіді лежали б необробленими в буферах ОС, а таблиця `rich.live` «завмирала» б (при запуску з `--debug` `asyncio` виводить попередження про блокування циклу понад `100 мс`). Саме тому краулер лише потоково записує сирі документи у `.jsonl`, а `findex index` виконується окремим кроком поза циклом подій.

### 4. Оброблений збій у `crawl.log` (`429 Too Many Requests` / `TimeoutError`)

При виникненні тимчасового збою сервера (`429`, `5xx`) або таймауту функція `fetch` виконує до 3-х спроб із `exponential backoff + jitter` (або чекає час, вказаний у заголовку `Retry-After`). Якщо після 3-х спроб сторінка все ще недоступна, помилка безпечно логується у `crawl.log` без аварійної зупинки `TaskGroup`:

```text
[2026-11-05 18:40:11] Status: 200 | URL: http://quotes.toscrape.com/ | Error: 
[2026-11-05 18:40:12] Status: 200 | URL: http://quotes.toscrape.com/page/2/ | Error: 
[2026-11-05 18:40:15] Status: 429 | URL: http://127.0.0.1:8765/rate-limit | Error: HTTP 429
[2026-11-05 18:40:19] Status: 0 | URL: https://httpbin.org/delay/12 | Error: TimeoutError
[2026-11-05 18:40:20] Status: 200 | URL: http://quotes.toscrape.com/tag/inspirational/ | Error: 
```

## Інструкція з запуску для перевірки

**1. Запуск краулера (потоковий збір сторінок у JSONL)**

```bash
uv run findex crawl http://quotes.toscrape.com/ --max-pages 200 --concurrency 5 --out data/crawl.jsonl
```

**2. Побудова індексу зібраних даних**
*(Програма автоматично розпізнає формат `.jsonl` через `iter_documents` і зберігає зворотну сумісність для `.txt` файлів)*

```bash
uv run findex index data/crawl.jsonl index.bin
```

**3. Виконання пошуку по зібраних цитатах**

```bash
uv run findex search index.bin "einstein"
```

**4. Запуск ізольованих тестів краулера (`httpx.MockTransport`, без живої мережі)**

```bash
uv run pytest tests/test_crawl.py -v
```
