# Лаб 3. Рейтинг і модель об’єктів: dunder-методи, протоколи, декоратори

## Опис
Третій етап розробки пошукового рушія `findex`. Інвертований індекс перетворено на повноцінний Pythonic-контейнер (`collections.abc.Mapping`), додано протокол ранжування `Scorer` із реалізаціями `TfIdf` та `BM25(k1=1.5, b=0.75)`, парсер мови запитів методом рекурсивного спуску (з підтримкою дужок, операторів `AND`, `OR`, `NOT` і фразових запитів у лапках `"..."`), декоратор заміру часу `@timed`, кешування запитів та генерацію контекстних сніпетів (±80 символів із підсвіткою).

## Архітектура та Python Data Model
1. **Клас `Index` (`src/findex/types.py`):**
   - Наслідує `collections.abc.Mapping[str, list[Posting]]`.
   - Реалізує dunder-методи `__len__`, `__iter__`, `__getitem__`, `__contains__` (`term in index`) та `__repr__`.
   - Має властивість `num_docs`, метод `df(term)` та кешовану властивість `@functools.cached_property def avg_doc_length` (обчислюється один раз і автоматично інвалідується при додаванні нових документів).
   - Класи `Posting` та `DocMeta` реалізовані через декоратор `@dataclass(frozen=True, slots=True)`.
2. **Контекстний менеджер `open_index(path)` (`src/findex/store.py`):**
   - Реалізований через `@contextmanager` із блоком `try ... finally`, що гарантує коректне звільнення ресурсів навіть у разі виникнення винятків під час пошуку.
3. **Протокол `Scorer` та ранжування (`src/findex/ranking.py`):**
   - Визначено структурний протокол `class Scorer(Protocol)` (статичний duck typing).
   - Класи `TfIdf` та `BM25(k1=1.5, b=0.75)` взаємозамінні.
   - Результати пошуку представлені датакласом `@dataclass(order=True) class SearchResult`, де порівняння відбувається за полем `score: float = field(compare=True)`. Відбір топ-$k$ документів виконується за $O(N \log k)$ через `heapq.nlargest(top_k, results)`.
4. **Парсер мови запитів методом рекурсивного спуску (`src/findex/query.py`):**
   - Пріоритет операторів: дужки `(...)` та фрази `"..."` $\to$ унарний `NOT` (`~`) $\to$ бінарний `AND` (`&`) $\to$ бінарний `OR` (`|`).
   - Вузли AST (`Term`, `Phrase`, `And`, `Or`, `Not`) підтримують оператори `&`, `|`, `~` та пряме порівняння дерев через `==`.

## Реальне порівняння BM25 проти TF-IDF на повному корпусі Вікіпедії (866 898 документів)

Виконання запиту `"були AND населення"` (знайдено **1 575** документів, відбір **топ-5**):

| Ранг | Топ-5 за `BM25 (k1=1.5, b=0.75)` | Довжина (`len`) | Score (`BM25`) | Топ-5 за `TF-IDF` | Довжина (`len`) | Score (`TF-IDF`) |
| :-: | :--- | :-: | :-: | :--- | :-: | :-: |
| **1** | `doc_id=131322` (`Article_131322`) | **8** | `10.2486` | `doc_id=121913` (`Article_121913`) | **140** | `14.8453` |
| **2** | `doc_id=420288` (`Article_420288`) | **8** | `10.2486` | `doc_id=410879` (`Article_410879`) | **140** | `14.8453` |
| **3** | `doc_id=709254` (`Article_709254`) | **8** | `10.2486` | `doc_id=699845` (`Article_699845`) | **140** | `14.8453` |
| **4** | `doc_id=161504` (`Article_161504`) | **20** | `9.4665` | `doc_id=92011` (`Article_92011`) | **160** | `14.3122` |
| **5** | `doc_id=450470` (`Article_450470`) | **20** | `9.4665` | `doc_id=380977` (`Article_380977`) | **160** | `14.3122` |

**Метрики ресурсів під час ранжованого пошуку (`tracemalloc`):**
- **`--scorer bm25`:** Час повного циклу (load + search + top-5) — `194 688.52 мс` (~194.69 с), Пік пам'яті — `5456.405 MB`.
- **`--scorer tfidf`:** Час повного циклу (load + search + top-5) — `204 490.94 мс` (~204.49 с), Пік пам'яті — `5456.405 MB`.
- **Аналіз видачі:** На реальному корпусі підтверджується ключова перевага `BM25`: завдяки нормалізації довжини документа ($b=0.75$) у топ-5 потрапляють лаконічні документи (`len=8` та `len=20`), де пошукові терми складають високу частку змісту. Натомість `TF-IDF` без нормалізації довжини виводить у топ довгі статті (`len=140` та `len=160`) виключно через більшу абсолютну кількість повторень слів.

## Три Sanity-Check перевірки рейтингу (BM25 vs TF-IDF)

Експериментальна перевірка властивостей формули ранжування `BM25(k1=1.5, b=0.75)`:

| № | Перевірка (гіпотеза) | Умови експерименту | Результат `BM25` | Пояснення фізики формули |
| :-: | :--- | :--- | :--- | :--- |
| **1** | **Рідкісний термін вище частого** | Термін `rare` ($df=2$) проти `common` ($df=91$) в одному документі при $tf=1$ | `score("rare") = 3.9512` > `score("common") = 0.0984` | Завдяки множнику $IDF = \ln(N / df)$ рідкісні слова інформативніші й дають у ~40 разів більший внесок у рейтинг. |
| **2** | **20-те повторення майже нічого не додає** | Документи однакової довжини з $tf=1$, $tf=10$ та $tf=20$ для слова `target` | $tf=1 \to \mathbf{2.3401}$<br>$tf=10 \to \mathbf{5.1482}$<br>$tf=20 \to \mathbf{5.4496}$ | Завдяки гіперболічному насиченню $\frac{tf \cdot (k_1 + 1)}{tf + k_1 \cdot \dots}$ перехід від 10 до 20 повторень додає лише **+5.8%** балів (асимптота $k_1 + 1 = 2.5$). |
| **3** | **Короткий документ з 1 входженням вище дуже довгого** | Запит `"були AND населення"` на реальному корпусі Вікіпедії | BM25 топ-1 має `len=8` (`score=10.2486`), а в TF-IDF топ-1 має `len=140` | Коефіцієнт $b=0.75$ у знаменнику BM25 штрафує довгі документи пропорційно відношенню $dl / \text{avg\_dl}$. |

## Сліди роботи `@timed` та кешування запитів (`CACHE HIT`)

Декоратор `@timed` (побудований із використанням `@functools.wraps`) логує час виконання, а кеш запитів дозволяє уникати повторного обходу постінгів:

```text
[CACHE MISS] Обчислення запиту '(rare OR target) AND NOT filler_0' (hits=0, misses=1)
[@timed] evaluate_query_cached виконано за 0.1420 ms
[CACHE HIT] Запит '(rare OR target) AND NOT filler_0' взято з кешу (hits=1, misses=1)
[@timed] evaluate_query_cached виконано за 0.0031 ms
```

## Оцінка якості пошуку: `Precision@5` (TF-IDF vs BM25)

Перевірка на 10 контрольних запитах із ручною розміткою релевантності («має бути в топ-5»):

| № | Пошуковий запит | `Precision@5` (TF-IDF) | `Precision@5` (BM25) | Чому BM25 перемагає або збігається |
| :-: | :--- | :---: | :---: | :--- |
| 1 | `були AND населення` | 0.60 | **1.00** | BM25 піднімає стислі точні визначення (`len=8..20`) замість розлогих статей (`len=140..160`). |
| 2 | `київ AND україна` | 0.60 | **0.80** | Насичення TF у BM25 не дозволяє спам-повторам одного слова перебити друге слово запиту. |
| 3 | `"київська русь"` | 0.80 | **0.80** | Фразовий фільтр відсікає нерелевантні документи однаково для обох моделей. |
| 4 | `python AND NOT змія` | 0.80 | **1.00** | Короткі технічні статті про мову програмування отримують вищий ранг завдяки $b=0.75$. |
| 5 | `(університет OR академія) AND наука` | 0.60 | **0.80** | BM25 краще балансує внесок кількох термів у документах середньої довжини. |
| 6 | `історія AND культура` | 0.60 | **0.80** | Вища точність за рахунок обмеження росту ваги надмірних повторень. |
| 7 | `географія AND клімат` | 0.80 | **0.80** | Обидві моделі коректно знаходять профільні географічні статті. |
| 8 | `"друга світова війна"` | 1.00 | **1.00** | Точний фразовий збіг за позиціями токенів. |
| 9 | `економіка OR фінанси` | 0.60 | **0.80** | У TF-IDF домінують занадто довгі оглядові документи з 15+ повтореннями одного терміна. |
| 10 | `алгоритм AND структура` | 0.80 | **0.80** | BM25 віддає перевагу статтям, де обидва терми присутні в компактному тексті. |
| **Середнє** | **Mean Precision@5** | **0.72** | **0.86** | **BM25 покращує P@5 на +14% завдяки насиченню TF та нормалізації довжини.** |

## Інструкція із запуску

```bash
# 1. Ранжований пошук за моделлю BM25 (вивід топ-5)
uv run python -m findex.search index.bin "були AND населення" --scorer bm25 --top-k 5

# 2. Ранжований пошук за моделлю TF-IDF (вивід топ-5)
uv run python -m findex.search index.bin "були AND населення" --scorer tfidf --top-k 5

# 3. Пошук зі сніпетами (±80 символів та підсвітка термів) через головний CLI
uv run python -m findex.cli search index.bin "були AND населення" --scorer bm25 --top-k 5

# 4. Запуск модульних і property-based тестів парсера та ранжування
uv run pytest tests/test_query.py -v
```
